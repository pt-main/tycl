# Changelog

Все значимые изменения **TYCL** (типизированный конфигурационный язык для Go).

Формат следует [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование следует [SemVer](https://semver.org/lang/ru/).

## [1.4.2]

### Changed

- **`lc` v2.0.1 -> v2.1.0.** Зависимость переведена на актуальный релиз.
  Правила лексера теперь принимают обычные строки с шаблонами вместо готовых
  регулярных выражений `regexp2`, а `stringParsing.NewLexer` сообщает об ошибке
  компиляции шаблона. Поэтому `lcproc.NewLexer` и `lcproc.NewParser` в пакетах
  `lang` и `contract` возвращают `(*T, core.ErrorInterface)`, и все места
  вызова обрабатывают ошибку. `regexp2` больше не нужна и удалена из `go.mod`.

### Fixed

- **Ошибки вложенных объектов терялись.** Некорректная пара внутри вложенного
  объекта заменялась общим сообщением "Invalid value for object" с указанием на
  внешний ключ: `lang.parseType` перезаписывал ошибку вложенного разбора, и слой
  диагностик показывал внешнюю пару вместо настоящей ошибки. Теперь ошибка
  вложенного объекта доходит до пользователя вместе со своей позицией.
- **Вложенные объекты разбираются на месте.** `parseNested` вызывал
  `configParser.parseObject`, которого не существует, поэтому проект не
  собирался. Разбор тела вынесен из `ParseBody` в отдельный `parseObject`,
  принимающий любой узел объекта; вложенный объект теперь разбирается по
  дереву, а не повторной лексикой его текста на каждом уровне вложенности.
- После рефакторинга удалён неиспользуемый `configParser.offsetOf`.

## [1.4.0] - 2026-09-29

Релиз о наблюдаемости и полноте CLI. Основная работа - плоский слой диагностик с
человекочитаемым выводом, стабильным JSON-конвертом и точными позициями в исходнике,
плюс переход на актуальные версии `lc` и `tap`.

### Changed

- **Зависимости переведены на актуальные версии.** `lc` обновлён с 1.5.4 до
  `github.com/pt-main/lc/v2` v2.0.1: путь модуля теперь с суффиксом `/v2`, все импорты
  в 18 файлах переписаны. `tap` обновлён с 1.4.8 до `github.com/pt-main/tap/go` v1.5.8 -
  в проекте Go-версия tap живёт во вложенном модуле `tap/go`, а корневой `tap` начиная с
  1.5.0 написан на Rust и Go-пакетов не содержит. Косвенная зависимость
  `github.com/pt-main/tap v1.4.7`, которую тянул `lc` 1.5.x, больше не нужна.
- Три вызова `parser3` переведены на новое API `lc` v2: поля `ParseError.Code` и
  `GrammarError.Code` переименованы в `Phase`, а в `parseHint` строковый литерал
  `"Expect"` заменён на константу `parser3.PhaseExpect`.
- Пересобран `go.sum`: удалены записи мёртвых версий `lc` (1.5.0-pre, 1.5.2-1.5.4) и `tap`
  (1.4.7, 1.4.8, 1.5.6).
- Форматирование сообщений об ошибках вынесено в отдельный пакет `format` с
  разделителями, указывающими на место в цепочке ошибок.
- Бинарники в `build/` удалены из репозитория: бинарные файлы не должны жить в
  истории репозитория, собираются скриптом `build.sh`.

### Added

- **Пакет `diag`** - плоский слой диагностик. Любая ошибка `lc` или `tycl`
  разворачивается в список структур, а не в цепочку: `diag.Diagnostic` несёт стабильный
  код, severity, сообщение, подсказку, `*Span` с позицией в файле, путь конфига и индекс
  массива.
- **Человекочитаемый рендер с кареткой** - `diag.Render` печатает строку исходника,
  номер и `^^^^` под ошибочным токеном. Отдельный путь кода не нужен: цвета резолвятся
  один раз в конце, поэтому `--no-color` и перенаправленный вывод работают одинаково.
- **Стабильный JSON-конверт** - флаг `--json` заставляет любую команду печатать один
  конверт `{ok, command, diagnostics, data}` в stdout и оставлять stderr пустым, чтобы
  результат можно было парсить без фильтрации.
- **Человекочитаемые подсказки** - `diag` переводит коды парсера в советы: отсутствие
  запятой перед `}`, комментарий перед открывающей `{`, пропущенное двоеточие перед типом.
- **Машинночитаемое дерево синтаксиса** - команда `tycl ast` отдаёт каждый узел с типом,
  исходным текстом и спаном. Это контракт языка для редакторов и сторонних инструментов.
- **Слой контрактов для проверки без CLI** - `diag.CheckContract` и `tycl.Validate`
  возвращают готовый список диагностик, `tycl.ProcessSource` подписывает их именем файла.
- **Поддержка stdin/stdout** - путь `-` читает из stdin и пишет в stdout, поэтому
  `cat app.tycl | tycl gen - - json | jq .port` работает как обычный пайп.
- **Предикативные коды возврата** - 0 успех, 1 некорректные данные, 2 ошибка
  использования, 3 ошибка ввода-вывода. Коды проверяются в `cli_test.go`.
- 547 строк тестов на CLI, 166 на диагностику, 245 на язык, 82 на контракты, 64 на
  форматирование.
- Тесты на разбор путей, слияние конфигов, значения и типизацию: `lang/path.go`,
  `lang/merge.go`, `lang/values.go`, `lang/typing.go`.

### Changed (CLI)

- **Команда `file` удалена.** Её субкоманды разошлись по самостоятельным командам с
  собственным разбором аргументов: `get`, `set`, `remove`, `structure`. Причина -
  у `file` был свой флаг `--path` и собственный синтаксис, из-за чего скрипты и
  подсказки редактора работали с разными формами одной команды.
  Миграция: `tycl file get --path=a.tycl int port` -> `tycl get a.tycl port`.
- `contract` и `contract.go` вынесены в пакет `contract`, `contract.go` в корне удалён.
- Каждая команда регистрируется через `adapt`, который централизованно печатает результат
  и выбирает код возврата.

### Added (CLI)

- Команды `query` (чтение нескольких путей или всех сразу), `ast`, `docs`, `types`,
  `merge` (поздние файлы побеждают, вложенные объекты сливаются по ключам), `version`.
- Флаги `--verbose` и `--debug` включают трассировку диспетчеризации команд от tap.
- `--no-color` принимается в обоих написаниях: с дефисом (документированное) и с
  подчёркиванием (то, которое проверяет сам tap).

### Fixed

- `tycl set` переписывает файл в каноническом виде и умеет менять тип ключа, не оставляя
  за собой старый дубликат.
- Неизвестные пути в `get`/`set`/`query` отклоняются с подсказкой "did you mean"
  вместо пустого значения или паники.
- `docs` и `types` больше не засирают stderr при нормальной работе.

### Removed

- Команда `tycl file` вместе с флагом `--path` (см. Changed).
- Корневой файл `contract.go` - контракты живут в пакете `contract`.
- `test/test.go` - покрытие перешло в пакетные `_test.go` рядом с кодом.
- Бинарные файлы из `build/` (см. Changed).

### Migration

- `lc` v1 -> v2: переписать импорты `github.com/pt-main/lc/...` на
  `github.com/pt-main/lc/v2/...`, затем `go get github.com/pt-main/lc/v2@v2.0.1`.
  Референсный скрипт миграции лежит в lc: `docs/to-2.0-migrate.sh`.
- `tap` -> `tap/go`: переписать `github.com/pt-main/tap/...` на
  `github.com/pt-main/tap/go/...`. Имя пакета остаётся `tap`, алиасы править не нужно.
- `tycl file <subcommand> --path=<file> ...` -> `tycl <subcommand> <file> ...`:

  | Было                                    | Стало                            |
  |-----------------------------------------|----------------------------------|
  | `tycl file get --path=c.tycl int port`   | `tycl get c.tycl port`           |
  | `tycl file set --path=c.tycl int port 9090` | `tycl set c.tycl port auto 9090` |
  | `tycl file remove --path=c.tycl int port`  | `tycl remove c.tycl port`        |
  | `tycl file structure --path=c.tycl`      | `tycl structure c.tycl`          |

- `tycl gen` теперь принимает `tycl` как тип вывода, а не только `json|yaml|toml`.
